Backend Systems

1. Architecture of Backend Systems

a) Monolithic vs. Microservices

  • Monolithic Architecture: A single, unified application where all components are tightly coupled.
  • Microservices Architecture: A distributed system where each service handles a specific function and communicates via APIs.

b) Layered Architecture

  • Presentation Layer: Handles HTTP requests (REST, GraphQL) and responses.
  • Business Logic Layer: Processes business rules and workflows.
  • Data Access Layer: Interacts with databases and external storage systems.

2. Web Servers & APIs

a) Web Servers

  • Handle client requests and serve responses (e.g., Nginx, Apache, Caddy).
  • Backend applications run behind these servers (e.g., Node.js, Spring Boot, Django).

b) APIs

  • RESTful APIs: Use HTTP methods (GET, POST, PUT, DELETE) with JSON responses.
  • GraphQL: A flexible query language for fetching required data.
  • gRPC: Uses Protocol Buffers for efficient, high-performance RPC communication.

3. Databases & Storage

a) Relational Databases (SQL)

  • Structured data with relationships (e.g., PostgreSQL, MySQL, Microsoft SQL Server).
  • Use SQL for querying data.

b) NoSQL Databases

  • Document Stores: MongoDB, CouchDB.
  • Key-Value Stores: Redis, DynamoDB.
  • Column Stores: Cassandra.
  • Graph Databases: Neo4j.

c) Caching Strategies

  • In-Memory Caching: Redis, Memcached.
  • CDN Caching: Cloudflare, AWS CloudFront.

4. Message Queues & Event-Driven Architecture

  • Used for asynchronous processing and decoupling services.
  • Message Brokers: Kafka, RabbitMQ, Amazon SQS.
  • Event-Driven Systems: Publish-subscribe models for scalability.

5. Authentication & Authorization

  • Authentication: Verifies user identity (OAuth 2.0, JWT, OpenID Connect).
  • Authorization: Determines user permissions (RBAC, ABAC, ACL).

6. Scalability & Performance

a) Load Balancing

  • Distributes traffic across multiple servers (e.g., Nginx, HAProxy, AWS ELB).

b) Horizontal vs. Vertical Scaling

  • Horizontal Scaling: Adding more machines.
  • Vertical Scaling: Increasing resources (CPU, RAM) of existing machines.

c) Database Replication & Sharding

  • Replication: Multiple copies for high availability.
  • Sharding: Splitting data across multiple databases for scalability.

7. Security Best Practices

  • Input Validation & Sanitization: Prevent SQL Injection, XSS, CSRF.
  • Encryption: Data at rest (AES), in transit (TLS/SSL).
  • Rate Limiting: Protects against DDoS attacks.

8. Observability & Monitoring

  • Logging: Collecting logs (ELK Stack, Loki).
  • Metrics: Monitoring performance (Prometheus, Grafana).
  • Tracing: Debugging distributed systems (Jaeger, Zipkin).
