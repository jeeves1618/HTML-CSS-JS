Image Generation

  • Docker Images

    Docker images are generated through three common approaches.

    1. Using Docker File
    We need to write a Docker file with the list of instructions which can be passed to docker server to generate a docker image based on the given instructions.
    2. Using Buildpacks
    A buildpack’s job is to gather everything your app needs to build and run, and it often does this job quickly and quietly. It is built on top of Docker and simplifies containerization since it doesn't require us to create a docker file.
    3. Using Google Jib
    Jib handles all steps of packaging your application into a container image. You don't need to know best practices for creating Dockerfiles or have Docker installed. Jib builds containers without using a Dockerfile or requiring a Docker installation. You can use Jib in the Jib plugins for Maven or Gradle, or you can use the Jib Java library.

  • Building for Docker

    Before creating a docker file, open the terminal in the folder with POM file and run the mvn clean install command to create a jar. By default, spring boot may create a war file. So, provide the <packaging>jar</packaging> override. Test if the application is coming up using the command mvn spring-boot:run

    ctrl + c will stop the application and you should also try starting the application using the java command java -jar target/Librarian-2.0.0.jar. This will ensure that you have the necessary maven plugin available in pom file before we start Dockerizing the project.

    Once this is done, please create the docker file and check if the docker is installed using the command docker version. This should list the Docker Client and Docker Desktop from your local.

  • Building

    Now that we have an idea of what a Docker is, we will see how we can Dockerize our code. I have a very basic Java Spring Boot application here.

    1. Add a Dockerfile to the project root directory.
    2. Run the command docker build -t my-first-docker-image .to create a docker image. The docker image is not alive and it just has the code, maven dependencies, run time (tomcat server in this case) and other utilities. Always specify the name of image prefixed by dockerhub account name. i.e dochubacctname/my-first-docker-image instead of my-first-docker-image
    3. Tag Docker Image using the command docker tag my-first-docker-image:latest {account name}/my-first-docker-image:v3
    4. You can also tag (version) the docker image in the build command itself. docker build -t my-first-docker-image:tag-name .
    5. docker images will list the docker image.
    6. Push Docker Image to Docker hub repository using docker push {account name}/my-first-docker-image.
    7. Pull Docker Image from docker hub repository.
    8. Run the pulled Docker image in to our local computer using docker run -p 8090:8080 {account name}/my-first-docker-image. The first port is the port where docker will expose the end point. The second port is the port bound to the application through the properties file or by default.

  • Docker Compose

    If we want to run multiple containers, which were already built, then we should use docker compose. Docker compose also establishes the bridge between containers from different network.

    Because each docker container has its own network, we cannot communicate across the containers using localhost.

    Once this is done, please create the docker file and check if the docker is installed using the command docker version. This should list the Docker Client and Docker Desktop from your local.
